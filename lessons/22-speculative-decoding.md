# 22｜既然有前後依賴，為什麼能一次驗證多個 token？

普通 decode 每次只取得下一個未知 token。若先用成本較低的模型草擬一段，大模型就有一段已知候選可用來平行驗證。候選仍需符合大模型的選擇規則，不能因為小模型比較快就全部照收。

設大模型目標分布為 p，小模型草稿分布為 q。從 q 抽到候選 x 後，使用接受率 min(1,p(x)/q(x))。若拒絕，從與 max(p−q,0) 成比例的殘差分布抽取修正 token。這個校正使單步輸出的邊際分布保持為 p。

用本課自訂數字 p=[0.6,0.3,0.1]、q=[0.5,0.2,0.3]：被直接接受的機率質量是 min(p,q)=[0.5,0.2,0.1]，總接受率 0.8。剩餘 0.2 的質量按 [0.1,0.1,0] 的比例補上，最終恰好回到 p。

執行 `python -m labs.run speculation`，直接驗證這個質量守恆。這是單步分布實驗；不是完整多 token 引擎，也沒有量測大模型速度。

多 token 驗證必須沿著被接受的前綴處理；一旦某處拒絕，後面的草稿不能照原樣沿用，相關暫存狀態也要修正。實作還需處理全部接受時的額外輸出與 cache 回退。

加速取決於草稿成本、接受率與驗證效率。草稿品質不佳、驗證成本高或服務已能充分 batching 時，收益可能不大。它也不保證固定 seed 下逐 token 等同某個原始實作；正確校正關注的是目標分布。

**練習：** 只保留小模型「看起來合理」的結果、拒絕後直接從 p 重抽，是否就是上述精確方法？

**答案：** 不是，拒絕後的分布需正確校正，否則可能引入偏差。

**閱讀：** [Fast Inference from Transformers via Speculative Decoding](https://proceedings.mlr.press/v202/leviathan23a.html)。
