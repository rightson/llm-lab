# 08｜不能偷看未來，為什麼還能平行處理？

假設訓練文字是「我 喜歡 蘋果」。在「我」的位置預測下一個 token 時，如果能讀到「喜歡」，就等於題目附上答案。因果遮罩讓每個位置只能看自己及前面的 token。

| 查詢位置 | 我 | 喜歡 | 蘋果 |
| --- | --- | --- | --- |
| 我 | 可見 | 遮住 | 遮住 |
| 喜歡 | 可見 | 可見 | 遮住 |
| 蘋果 | 可見 | 可見 | 可見 |

這張三角形遮罩限制的是**資訊依賴**，不要求每個格子依序執行。同一層的輸入都已知時，可以把所有位置的矩陣運算一起送入硬體，再遮掉不合法的連結。層與層之間仍有依賴。

生成新文字的情況不同：還沒選出下一個 token，就沒有該 token 的 embedding 可以送入後續步驟。訓練或 prefill 的輸入已知，普通 decode 的未來輸入未知；兩者不能混為一談。

一套 Q/K/V 只有一種學到的配對方式。Multi-head attention 同時使用多套投影，分別聚合，再合併輸出。各 head 可以學到不同關係，但不保證每個都有清楚的人類語意分工。

MHA 通常每個 query head 有自己的 K/V head；MQA 共享一組 K/V；GQA 則由多個 query head 共用一組 K/V。共享能降低 KV 儲存量，但它涉及模型架構與訓練，不是對任意既有模型任意刪掉快取。

**練習：** 對 `[1,2,3]` 與 `[1,2,3,8,9]` 做因果模型 forward，前三個位置的 logits 應相同嗎？

**答案：** 相同，容許浮點誤差；未來 token 不得影響前面的表示。`test_causal_prefix_independence` 直接驗證這個性質。
