# 01｜為什麼「猜下一個片段」能寫出整段回答？

假設你看到「今天下雨，出門記得帶」。你可能接「傘」，也可能接「雨衣」。前文縮小了合理後文的範圍。語言模型要學的，就是把這種關係變成可計算的機率。

先不用想整篇文章。設前文為 x，候選片段為 y，P(y｜x) 表示「已知 x 時，下一個片段是 y 的機率」。下面是自訂教學數字：

| 下一個片段 | 機率 |
| --- | ---: |
| 傘 | 0.60 |
| 雨衣 | 0.30 |
| 餅乾 | 0.10 |

選到「傘」後，模型把它接回前文，再預測後面的片段。每一步的條件都在改變，因此不是把同一張機率表抽很多次。

整段輸出的機率可以拆成：

$$P(y_1,\ldots,y_m\mid x)=\prod_{t=1}^{m}P(y_t\mid x,y_1,\ldots,y_{t-1})$$

讀法：先算第一個片段的機率，再乘上已經知道第一個片段時，第二個片段的機率，如此繼續。這是機率的連鎖法則；真正困難的工作，是學好每一步的條件機率。

預測單位叫 token，未必是一個中文字或英文單字。模型輸出的是 token 分布，生成系統才依策略選出一個。一般自回歸生成存在前後依賴：不知道剛選到什麼，就還不知道下一步完整的輸入。

這也解釋一個限制：一段話接得順，不保證它符合現實。學會常見的語言與推理模式，和擁有即時、經過驗證的事實，是不同的能力。

**動手想：** 如果第一步「傘」的機率是 0.6，接著句號的條件機率是 0.5，「傘。」這條路徑的機率是多少？

**檢查答案：** 0.3。不是相加，因為兩個條件必須沿同一條生成路徑成立。

**完成標準：** 能說明為何輸出一百個 token，一般需要反覆更新前文；也能區分「下一個 token 最可能」與「整段答案一定正確」。
