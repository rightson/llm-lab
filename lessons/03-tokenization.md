# 03｜電腦如何把文字切成可處理的單位？

直接把「一個單字」當單位會碰到問題：新名字、拼字錯誤、程式碼，以及沒有空格分詞的語言，都可能不在字典裡。若每個位元組都是一個單位，又可能讓序列很長。Tokenizer 在詞彙表大小與序列長度之間取捨。

最簡單的可逆方法是 UTF-8 位元組編碼。例如「重」在 UTF-8 佔三個 bytes，但它只是一個 Unicode 字元。字元數、byte 數與模型 token 數是三種不同的計數。

執行 `python -m labs.run tokens`。第一段使用 byte tokenizer，每個 byte 對應 0–255 的整數，因此沒有未知 byte。第二段示範固定合併規則：

| 步驟 | banana 的片段 |
| --- | --- |
| 起始 | b / a / n / a / n / a |
| 合併 a+n | b / an / an / a |
| 合併 b+an | ban / an / a |

這只是示意，不是某個現成模型的真正切法。BPE 類方法會根據訓練語料學習合併規則；推論時則按既定規則切分。不同模型的詞彙表、前處理與特殊 token 可能不同，因此同一句話可能有不同 token 數。

Token ID 是查表索引。ID 100 不比 ID 20「意思多五倍」；整數大小本身不具有語意距離。聊天室還會使用角色與邊界標記，所以送入模型的內容通常不只有你看見的那段文字。

**練習：** 同一段中文比英文耗用更多 tokens，能否直接推論模型的中文推理能力較差？

**答案：** 不行。這先反映切分效率；能力還取決於訓練資料、模型與任務。切分較碎會增加 context 與計算成本，但不能單獨代表理解能力。
