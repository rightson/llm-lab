# LLM Lab 完整學習規劃：先理解，再實作，最後用硬體檢驗理解

## 專案的北極星

**讓讀者對 LLM 建立能推導、能預測、能用實驗修正的直覺。** 程式讓概念可以操作，數學讓解釋精確，系統分析讓成本可見，RTL 讓運算與資料移動具體化。所有深入內容都必須回到「這讓我更理解 LLM 的哪一件事？」。

完整路線仍保留自有 NPU 與 Python/RTL 共同模擬。NanoNPU 僅是參考；llm-lab 的問題、演算法與架構由本專案主導。硬體課不搶走前段的學習重心，也不要求先懂 IC 設計才能理解 attention。

這份規劃取代「24 篇短講讀完，再一路上 48 篇硬體課」的線性想像。既有 24 課與 48 項硬體規劃保留，重新安排成有先備關係、可以反覆回訪的路線。C01–C40 是學習單元 ID，不是宣稱已新增 40 篇完成文章。

## 怎樣才算有 intuition？

遇到一個機制，至少做到四件事：

1. **解釋需求：** 不靠先背名詞，說出它要解決什麼問題。
2. **預測改動：** 移除它、改參數或換輸入時，先寫下預期結果。
3. **追蹤機制：** 能指出哪些數值、資訊依賴或資料流會改變。
4. **處理反例：** 實驗不符合預期時，知道哪個假設需要修正。

例如「KV cache 讓生成更快」只是記憶；能說明因果遮罩為何使舊 K/V 不變、快取省掉什麼卻仍要讀取什麼，並預測長 context 下的成本，才是此處的理解目標。

## 目前教材的缺口

既有教材已能追蹤 forward、sample、cache 與部分效能機制，但不足以支撐完整的學習終點：

- `TinyDecoder` 使用隨機權重，只能驗證機制。不能把它的 hidden state 或輸出當成語言能力證據。
- `training` 是獨立 bigram 實驗。還缺 context model、完整 Transformer 的訓練與泛化比較。
- 反向傳播、梯度檢查、資料切分、過擬合與 controlled ablation 尚未建立完整實驗。
- 缺少一組跨章節共用的模型、資料與 trace，讓讀者看見同一個預測如何走到張量、記憶體與時脈。
- 模型行為、能力與限制的討論，需要接回可觀察任務，不能只靠機械運算或「下一個 token」口號。
- 現有 NPU 是起始模型與 PE RTL 草案；尚未與已訓練模型或 RTL simulator 接通。

因此下一輪優先補「學會與泛化」，再進一步擴展硬體。以下所有新增內容均為規劃，完成狀態另見 [進度與交付順序](learning-progress.md)。

## 一條貫穿全程的任務

使用可控的合成語言建立關聯查找任務，例如：`甲=紅；乙=藍；問甲→`，期望輸出 `紅`。這不是聲稱查找等於語言理解，而是把「必須讀取前文」變成能精確驗證的最小問題。

每次隨機改變鍵值配對、查詢位置與干擾項；訓練與測試以獨立範例及組合切分，避免模型只記住「甲通常配紅」。另外加入位於相同範圍內的新組合測試，以及獨立報告的長度外推測試。已學位置表範圍以外的輸入不能直接宣稱支援。

| 版本 | 我們刻意限制什麼 | 要觀察什麼 |
| --- | --- | --- |
| V0：字頻/unigram | 完全忽略 context | 頻率先驗能做到多少？ |
| V1：bigram | 只看前一個 token | 為什麼最後一個符號相同仍可能需要不同答案？ |
| V2：固定視窗 MLP | 只看最近 k 個 tokens | 證據移出視窗時會發生什麼？ |
| V3：單層 attention model | 加入可讀取前文的通路 | 能否學到任務？改 mask/打亂配對後如何？ |
| V4：小型 Transformer | residual、norm、FFN、多層 | 哪些改動提高訓練穩定性或 held-out 表現？ |
| V5：推論與整數版本 | cache、量化、不同執行順序 | 哪些結果應等價？哪些是有品質代價的近似？ |
| V6：CPU＋RTL 版本 | 一部分 kernel 移到自有 NPU | 相同輸入能否通過 bit-level 與任務層級檢查？ |

只驗證這項任務不足以證明一般語言能力。再增加小型自然文字資料，事先確認來源與授權，用 held-out loss/perplexity、生成樣本與任務測試補充。合成任務用來隔離機制，自然文字用來觀察較真實的限制；兩者的結論分別報告。

## 八個階段、四十個學習單元

每個單元先教一個核心問題，再做最小算例與實驗。數學只在推導需要時引入；數學補充、程式追蹤與硬體實作分層呈現。表中的「既有支援」只是可重用材料，不代表深度版或新增實驗已完成。

### A. 模型到底在解什麼問題？C01–C05

先備：四則運算、比例。目標：理解條件分布與逐步生成，避免把「接字」誤認為查表或完整的人類認知解釋。

| 單元 | 核心問題與必要推導 | 實驗與理解檢查 | 既有支援 |
| --- | --- | --- | --- |
| C01 | 同一句前文為什麼有多個合理後文？由計數建立條件機率 | 自己列分布，改 context 後先預測排名 | 01 |
| C02 | 一步的預測如何組成整段文字？連鎖法則與誤差傳播 | 小型機率樹；比較局部 greedy 與整段路徑 | 01、11 |
| C03 | 為什麼需要 token？字元、byte、詞彙表、序列長度取捨 | 相同文字換切法，追蹤 ID 與可逆解碼 | 03、`tokens` |
| C04 | 模型權重、context、外部資料各保存什麼？ | 改 context 不更新權重，對照一次真正訓練更新 | 02 |
| C05 | 怎麼判斷模型學到東西？baseline、train/test 與洩漏 | 建立平衡測試與 unigram/bigram baseline；說明 chance baseline | 02 部分；新評估資料待建 |

**Gate A：** 能解釋機率與真實性的差異；同一批資料能給出 baseline 與獨立測試結果。不能只拿漂亮生成樣本通關。

### B. 文字如何成為可運算的表示？C06–C10

先備：A。目標：從 scalar 到 matrix，理解 representation 是可學習的編碼，而不是預先命名的語意座標。

| 單元 | 核心問題與必要推導 | 實驗與理解檢查 | 既有支援 |
| --- | --- | --- | --- |
| C06 | 向量、點積、矩陣到底做什麼？ | 手算 2×2；給任意 shape 推出合法輸出 | 04 |
| C07 | ID 為什麼不直接當語意大小？one-hot 到 embedding lookup | 重新編號 token、同步重排表格，預測是否改變運算 | 03、05 |
| C08 | embedding 在什麼條件下形成有用結構？ | 比較訓練前後；選定任務測表示，避免憑一張投影圖定義語意 | 05 部分；訓練觀察待建 |
| C09 | 為何矩陣乘法還不夠？線性組合與非線性 | 比較線性與小 MLP 的有限任務容量，控制參數/資料差異 | 04、09 部分 |
| C10 | 順序從哪裡來？位置與內容如何共同表示？ | 交換 token 順序；對照有/無位置資訊與任務結果 | 05、08 部分 |

**Gate B：** 能沿一個輸入寫出 shape、查表與投影；知道未訓練向量不代表已學語意。硬體預覽可看 CD01 的一次乘加，但不要求學 ISA 或 SRAM。

### C. 模型如何從錯誤中學習？C11–C15

先備：B；在此教 log、導數與鏈式法則所需的最小概念。目標：讓「權重是學來的」變成讀者親手驗證的因果過程。

| 單元 | 核心問題與必要推導 | 實驗與理解檢查 | 既有支援 |
| --- | --- | --- | --- |
| C11 | 為什麼用 cross-entropy？logits→softmax→loss | 比較對正確答案信心不同的 loss；手算一筆 | 02、07、10 |
| C12 | 參數要往哪個方向改？有限差分到 gradient | 對小 loss 改一個權重，預測正負方向與步長效應 | 待新增 |
| C13 | 多層如何一起學？chain rule、backprop、autograd | 小網路手推/NumPy gradient 對有限差分；再與框架對照 | 待新增 |
| C14 | 學到訓練集為什麼還不夠？視窗、容量、regularization | 訓練 V1/V2，比較 train/test gap 與證據超出視窗的失敗 | bigram 已有；MLP 待新增 |
| C15 | 失敗是模型不會、資料不夠，還是程式錯？ | overfit tiny batch、learning-rate sweep、多 seed、固定 split | 待新增 |

**Gate C：** gradient check 達事先選定容差；可以 overfit 小 batch；held-out 結果有對照。讀者能說明 loss 降低仍不代表泛化。這個 gate 必須早於完整 NPU 整合，不能再排在硬體課末尾。

### D. Attention 如何讓模型使用 context？C16–C20

先備：B、C。目標：把 Q/K/V 從比喻變成可計算、可訓練、可干預的資訊路徑。

| 單元 | 核心問題與必要推導 | 實驗與理解檢查 | 既有支援 |
| --- | --- | --- | --- |
| C16 | 平均所有位置為什麼不足？內容相依的加權讀取 | uniform average 與可學 attention 比較；改相關與無關資料 | 06 |
| C17 | 為何有 Q、K、V 三個角色？投影、縮放、softmax | 2–3 tokens 完整手算；分別只改 K 或 V，先預測結果 | 06、07、`attention` |
| C18 | 看不到未來為何仍能平行算？mask 與 label shift | 故意漏 mask/錯位 label，觀察 loss 假象；future independence | 08、既有因果性測試 |
| C19 | 多頭與位置處理增加了什麼？ | 控制參數預算比較 heads；learned position 與 RoPE 分開驗證 | 05、08 概念；實驗待新增 |
| C20 | attention 能學到查找嗎？能從權重圖判斷原因嗎？ | 訓練 V3；干預配對/刪證據/改查詢，與觀察權重分開報告 | 待新增 |

**Gate D：** 手算與程式相符；受控查找任務改善有 held-out 證據；能區分「這個 head 看起來關注某處」與「干預後證明此處對任務有影響」。不要求預先保證所有架構都能學會。

### E. Transformer 的各部分為什麼要一起存在？C21–C25

先備：C、D。目標：從可讀的 block 到真正訓練的小模型，用消融理解設計取捨。

| 單元 | 核心問題與必要推導 | 實驗與理解檢查 | 既有支援 |
| --- | --- | --- | --- |
| C21 | residual 只是把舊值加回去嗎？ | 追蹤表示與梯度；有/無 residual，匹配訓練預算 | 09 部分 |
| C22 | normalization 在控制什麼？為何放前/放後？ | 觀察尺度/梯度；LayerNorm、RMSNorm 的差異分開推導 | 09 部分 |
| C23 | FFN 對每個位置做什麼？為何 attention 之外還要它？ | 移除 FFN、改 hidden width；報容量與訓練成本混雜因素 | 09 部分 |
| C24 | 能否從零訓練完整小型 Transformer？ | V4：固定 tokenizer、split、seed、checkpoint；logits 與 loss trace | 隨機 forward 已有；完整訓練待新增 |
| C25 | 深度、寬度、context、資料量如何影響能力？ | 一次改一個主因，多 seed/預算對照，作小規模 ablation report | 待新增 |

**Gate E：** 一個真正學到可量測任務的小模型，加上至少一項成功與一項失敗的消融解釋。保留學習版模型（learned positions、LayerNorm、簡單 FFN）作基準；RoPE/RMSNorm/SwiGLU 是後續變體，不能偷偷換架構還比較舊權重。

### F. 學好的模型如何生成？能做什麼、不能證明什麼？C26–C30

先備：E。目標：把訓練時的平行計算、推論時的序列依賴與實際行為接起來。

| 單元 | 核心問題與必要推導 | 實驗與理解檢查 | 既有支援 |
| --- | --- | --- | --- |
| C26 | 最後一個向量如何形成下一 token 分布？ | 對已訓練 checkpoint trace hidden/logits/probability | 10；訓練版待接 |
| C27 | greedy、temperature、top-p 改了什麼？ | 固定模型比較分布、多樣性與任務正確率；不把流暢當正確 | 11、`sampling` |
| C28 | prefill/decode/KV 的等價性從哪裡來？ | 同一 checkpoint 做 full/cached/不同 chunk 比對；注入 offset bug | 12–14、`cache` |
| C29 | streaming、EOS、停止與 context 邊界如何工作？ | token/byte/event 分離；截斷證據、改輸出長度、檢查狀態釋放 | 14、`generation` 部分 |
| C30 | 為何學會續寫不等於可靠助理？ | 區分預訓練、指令調整、context 中使用資訊與外部檢索；證據缺失/衝突測試 | 01、02、23 部分；行為套件待新增 |

**Gate F：** 可生成並評估小模型輸出，能解釋來源於權重/context/外部資料的差別。SFT、偏好訓練與推理模型在此先定位它們改變哪個環節；完整 RL 訓練不塞入一課，也不是自有 NPU 的先決條件。

| --- | --- | --- | --- |
| C31 | 第一個字慢與後面每個字慢有何不同？ | 定義 TTFT/ITL/TPOT，分開 queue、運算、輸出；記錄量測邊界 | 16、`timing` |
| C32 | 權重、activation、KV 各吃多少空間？ | 手算後核對陣列 nbytes，追蹤 context/batch 與 GQA | 15、`memory` |

| --- | --- | --- | --- |

| C37 | 同一公式如何成為數值與時序規格？ | float→integer→PE→mesh；scale、wrap、stall 與 tail tile | CD01；完整 RTL 待驗證 |

**Gate H：** Python 驅動的是已編譯 RTL simulator，支援 kernel 的輸出與 bit-accurate reference 一致，再驗證小模型品質。記憶體延遲若為假設需標記；cycles 不能未經時脈證據就改寫成真實 tokens/s。FPGA/tape-out 均不是此 gate 的必要條件。

## 同一個 attention，我們回訪五次

| 回訪層次 | 當次只回答什麼 | 必須留下的證據 |
| --- | --- | --- |
| 直覺 | 目前位置為何需要選擇性讀取前文？ | 自訂例子與移除證據後的預測 |
| 數學 | 權重與加權內容怎麼算？ | 2–3 tokens 手算表與 shape |
| 學習 | Q/K/V 的參數能否從資料學出任務？ | 訓練曲線、held-out 測試、干預 |
| 系統 | 同一答案能否少寫回中間矩陣？ | 等價性、live set、I/O 比較 |
| 硬體 | tile、SRAM、pipeline 如何承接運算？ | 數值契約、cycle trace、RTL 比對 |

五次共用變數、資料與模型 lineage。讀者不必第一次接觸 attention 就同時處理 online-softmax、SRAM banking 與 RTL。

## 一次學習的節奏

建議將「理解」與「實作」拆成兩次可獨立完成的 session：先用約 20–30 分鐘閱讀、手算與寫下預測，再按個人熟悉度安排實驗。這是安排建議，不是每篇的固定篇幅或完成時間保證。

每個階段最後留一次整合與回顧：換一個沒看過的 shape 或輸入，要求先解釋再跑程式。若 gate 沒通過，回到對應缺口；不用按日曆硬推進。這份規劃不新增自動發布排程。

### 兩種完成標準，同一個專案

- **LLM 理解主線完成（A–G）：** 從資料訓練小模型，能推導 forward/learning/generation，能預測干預與資源成本，能辨識結論邊界。這是本 repo 必須先守住的核心成果。
- **完整共同設計路線完成（A–H＋所需硬體支線）：** 同一模型接到自行設計的 RTL，用 Python 驗證並比較成本。這仍是本專案保留的深度終點。

原 [48 項硬體規劃](codesign-roadmap.md) 供 H 階段按需展開，不是 48 個與 LLM 脫節的額外考試。STA/PPA 是更深的物理驗證延伸；沒有 tape-out 不妨礙功能共同模擬終點。
